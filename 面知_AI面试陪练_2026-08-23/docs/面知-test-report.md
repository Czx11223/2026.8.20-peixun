## 三、发现的问题与修改建议

### T-01 ｜ 移动端底部导航缺失「能力看板」「帮助」 【一般】
- **现象**：`page-template.html` 移动端底部导航仅 4 项（面试/题库/报告/我的），而桌面端顶部导航为 5 项（模拟面试/题库管理/面试报告/能力看板/帮助）。「能力看板」与「帮助」在移动端无任何入口。
- **影响**：手机端用户无法访问能力看板（FR-07）与帮助中心（FR-10），功能不可达。
- **证据**：`page-template.html` 第 154–160 行（顶部导航 5 项）、第 197–202 行（底部导航 4 项）。
- **修改建议**：统一移动端导航与桌面端语义。二选一：① 底部导航增为 5 项（面试/题库/报告/看板/我的），帮助并入「我的」二级页；② 底部导航保持 4 项，但「我的」页内聚合能力看板与帮助入口。开发规划 M5 需显式验收此覆盖。

### T-02 ｜ 两套导航模型冲突（同一产品两种 IA） 【一般】
- **现象**：早期《Web 信息架构》采用 4 项扁平导航（开始练习 / 面试记录 / 能力成长 / 我的），模拟面试作为「开始练习」内全屏向导；而后续 Axure 线框与 `page-template.html` 采用 5 项功能导航（模拟面试 / 题库管理 / 面试报告 / 能力看板 / 帮助），模拟面试为常驻一级入口。
- **影响**：开发缺乏唯一权威 IA，易致页面路由、路由守卫、面包屑、底部导航实现分歧。
- **证据**：`AI面试陪练_信息架构.html`（4 项）vs `page-template.html`（5 项）。
- **修改建议**：在开发规划中明确**唯一权威导航模型**（推荐 5 项功能导航，更贴合 Axure 终稿与页面模板），并反向修订信息架构文档，消除双轨。此项应在 M1 脚手架前敲定。

### T-03 ｜ 平板断点侧边栏文字溢出 【一般】
- **现象**：`@media (min-width:768px)` 将 `.app-sidebar` 设为 64px（折叠态），但侧边项 `<span>` 文本未隐藏；64px 宽减去内边距(24px) 后仅 40px，图标(18px)+间距(10px) 已占 28px，文本「普通模拟/压力面模拟/互联网…」被裁切或溢出。
- **影响**：768–1023px（平板/小窗）侧边栏显示异常，文字残缺，可读性差。
- **证据**：`page-template.html` 第 118–123 行（min-width:768 设 width:64px，未隐藏 span）。
- **修改建议**：在折叠态（768–1023px）对 `.side-item span` 设 `display:none`，仅留图标；或将该断点侧边栏宽度提升到能容纳文本的最小宽度（如 160px）。推荐前者（图标导航更简洁）。

### T-04 ｜ 字体规范遗漏「钉钉进步体」回退 【优化】
- **现象**：用户原始设计需求明确要求 `PingFang SC（回退钉钉进步体）`，但实际 `--font-sans` 为 `'PingFang SC','SF Pro Text',-apple-system,BlinkMacSystemFont,'Segoe UI',sans-serif`，未包含钉钉进步体。
- **影响**：规范未落实用户明确要求；且钉钉进步体非 Web 标准字体，即使加入也需提供 @font-face 与字体文件，否则无效。
- **证据**：`面知-design-system.html` 第 34 行；用户设计需求原文。
- **修改建议**：若确需钉钉进步体，应在 Design System 增加 `@font-face`（自托管 woff2，符合"零成本"）并加入回退链；否则在规范中明确"因字体可用性，回退链以系统字体为主"，并同步修订原始需求措辞，避免歧义。

### T-05 ｜ 非功能需求表述歧义 【一般】
- **现象**：原始 NFR「API响应<500ms，<2<3s，首屏加载<2s」中 `<2<3s` 语义不清。PRD 已自行解读为"AI 点评/转写 2–3s"，但来源需求未澄清，存在验收口径分歧风险。
- **影响**：性能验收标准可能被理解为"所有接口<3s"或"AI 接口<3s、普通接口<500ms"，直接影响 AC 设计与压测。
- **证据**：`面知-PRD.md` NFR 章节；用户原始需求。
- **修改建议**：将 NFR 显式拆为三档并写入 PRD 验收表：① 普通 CRUD 接口 P95 < 500ms；② AI 点评/语音转写 P95 < 3s（流式首字 < 1.5s）；③ 首屏 LCP < 2s。消除歧义。

### T-06 ｜ AI 语音容错前置不足 【一般】
- **现象**：M2（核心链路）即引入 ASR 语音识别作为 headline 功能，但"ASR 失败降级文字作答"仅在 M5 规划。M2 阶段若遇断网/麦克风拒绝/识别失败，语音作答链路无降级，可能卡死或静默失败。
- **影响**：核心卖点功能在弱网/异常环境不可用且无兜底，演示与自用风险高。
- **证据**：`面知-dev-plan.md` 里程碑 M2（引入 ASR）vs M5（异常兜底）。
- **修改建议**：将 ASR 降级逻辑（失败→自动切换文字作答 + 友好提示）**前移至 M2**，作为语音功能的"必带容错"而非 M5 打磨项；并在 PRD FR-03 验收标准中明确"语音不可用时可无缝降级文字"。

### T-07 ｜ 文档依赖外部 CDN（mermaid） 【优化】
- **现象**：`面知-PRD.html` 与 `面知-dev-plan.html` 通过 `https://cdn.jsdelivr.net/npm/mermaid@10` 渲染流程图，离线/内网环境无法渲染（源码以 `<pre><code>` 保留，可读但不可视）。
- **影响**：与产品"零/极低费用、本地缓存"理念略有冲突；内网评审或离线时流程图不可见。
- **证据**：`面知-PRD.html` 第 847 行。
- **修改建议**：① 文档交付同时附 Markdown 源（已具备，源码即流程图文本）；② 或构建时本地打包 mermaid（npm i mermaid 本地引入），去除 CDN 依赖。优先级低，仅文档体验优化。

### T-08 ｜ 空/异常态未实现 【优化】
- **现象**：`page-template.html` 对"无面试记录""错题本为空""加载失败""AI 超时"等空/错误态仅有 TODO 注释，原型未演示对应 UI。
- **影响**：学生首次使用（零数据）易遇空白页，焦虑感上升；异常态缺失降低健壮性观感。
- **证据**：`page-template.html` 第 143、210 行 TODO。
- **修改建议**：在 Design System 增加 `AppEmpty`（空状态）与 `AppError`/`AppLoading` 组件规范（骨架屏 + 重试按钮），并在 M5 全页面补齐；首页/记录页必须含有数据空态示例。

### T-09 ｜ 压力面模式未确认为一等参数 【优化】
- **现象**：PRD 将"压力面模拟"列为重要差异化能力，但开发规划 API 契约/面试状态机未显式列出 `mode=pressure` 字段，存在实现时遗漏风险。
- **影响**：压力面可能与普通面共用逻辑，缺少难度/追问/语气差异化参数，导致功能名不副实。
- **证据**：`面知-dev-plan.md` API 契约（需确认 interview 创建体是否含 mode）。
- **修改建议**：在 `/interview/start` 请求体显式定义 `mode: normal | pressure`，并在状态机/提示词模板中区分两类面试的追问策略与评分宽松度；PRD FR-02 验收补充"压力面应呈现明显更高追问密度与压迫语气"。

### T-10 ｜ 无障碍细节缺失 【优化】
- **现象**：SVG 图标与底部导航项缺 `aria-label`；折叠态侧栏仅靠图标无文本替代；seg 已加 `aria-selected` 但 nav/bottom-nav 无 `aria-current`。
- **影响**：屏幕阅读器用户（含视障考生）无法感知导航与图标含义，不符合基础 a11y。
- **证据**：`page-template.html` 第 198–202 行等。
- **修改建议**：为所有图标按钮、导航项补充 `aria-label`/`title`；当前页用 `aria-current="page"`；折叠侧栏图标加 `aria-label`。属低成本高收益项，建议 M5 一并纳入。

### T-11 ｜ 评分等级色彩映射建议固化到组件 【优化】
- **现象**：S/A 绿、B 橙、C/D 红 目前仅为文字约定，组件规范中虽有 badge-success/warning/error，但未显式规定"等级→badge 色"的映射示例。
- **影响**：跨页面（报告页/看板/记录列表）评分色若由各页自行实现，易不一致（P0 缺陷红线）。
- **证据**：`面知-design-system.html` 语义色章节 vs `component-specs.md`。
- **修改建议**：在 `component-specs.md` 增加「评分等级→色彩」映射表与 `AppGradeBadge` 组件（输入 S/A/B/C/D 自动着色），强制所有页面复用，杜绝跨页不一致。

## 五、下一步测试建议（第二轮）
1. **MVP 代码落地后**：对 M2 面试会话链路做端到端冒烟（开启→作答→实时点评→报告）。
